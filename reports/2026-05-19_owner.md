# AYCB v2 — Session Report 2026-05-19

## What We Did

Audited the "Sequential Run" (cascade) system end-to-end to verify that
when running a chain of nodes, each node really finishes — and writes
its output — before the next one starts reading from it.

## What Changed

No code. Investigation only. Findings + a memory note saved for the
fix session.

## Current State

- The cascade core works correctly for all **synchronous** nodes:
  Generate Image, LLM, Image Edit, Image Merge, Image Analysis,
  Flux-Cloud (with internal polling). Chain waits, output is in place
  before the next node reads it.
- **Generate Video has a real bug**: its `run()` returns the moment
  the request is submitted, not when the video is ready. The polling
  that writes the final `mediaId`/`videoUrl` runs decoupled in the
  background. So a chain like `Prompt → GenerateVideo → VideoAnalysis`
  breaks — the analyzer starts before the video exists.
- Three minor smells noted (defensive 100ms delay in Batch node,
  race condition in cascade-running guard, Image Edit ×N keeping only
  the first variant).

## Next Session

Fix Generate Video so it awaits the full polling before resolving,
so chains containing video generation work the same as image chains.
Optional cleanup of the Batch node delay at the same time.
