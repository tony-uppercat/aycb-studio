### Task 10: Hardening — cascade video fix

**Files:**
- Modify: `frontend/src/nodes/generate-video/useGenerateVideo.ts` (run ~line 434, startPolling ~306, stopPolling ~299, stop-signal effect ~401)
- Test: `frontend/src/nodes/generate-video/useGenerateVideo.test.ts` (create if absent; check for existing test file first)

**Interfaces:**
- Consumes: `registerNodeRun` contract in `frontend/src/utils/cascadeRun.ts` — `executeCascade` awaits each registered `fn()`; the fix makes GenerateVideo's promise span the full render.
- Produces: `run(): Promise<void>` that resolves only on terminal state (completed / failed / stopped / stale-request).

Bug: `run()` resolves right after submission (`startPolling(reqId)` is fire-and-forget `setInterval`), so a cascade continues while the video still renders and downstream consumes a stale/empty `videoUrl`.

- [ ] **Step 1: Write failing test** — mock `api.generateVideo` returning `request_id`, mock `api.videoStatus` returning `processing` twice then `completed` with url; assert `await run()` resolves only after the `completed` poll (e.g. videoUrl set when promise settles). Use fake timers.

- [ ] **Step 2: Run test** — Expected: FAIL (run resolves before completion).

- [ ] **Step 3: Implement completion promise**

```ts
// near pollRef declarations
const doneResolveRef = useRef<(() => void) | null>(null)
const settleRun = useCallback(() => {
  doneResolveRef.current?.()
  doneResolveRef.current = null
}, [])
```

- Call `settleRun()` in every terminal branch inside the poll interval: completed (after `setLoading(false)`), failed, stale-request catch branch.
- Call `settleRun()` in the `data._stop` effect and in the unmount cleanup (`useEffect(() => () => { stopPolling(); settleRun() }, ...)`) so a stopped/unmounted node never deadlocks a cascade.
- In `run()`, replace the tail after `startPolling(reqId)`:

```ts
startPolling(reqId)
await new Promise<void>(resolve => { doneResolveRef.current = resolve })
```

- The submit-error catch path needs no change (it already returns before polling).
- Note: resume-polling on mount (~line 391) intentionally does NOT create a promise — no cascade is awaiting it.

- [ ] **Step 4: Run test** — Expected: PASS. Also run full vitest.

- [ ] **Step 5: Manual chain check** — Lite UI: PromptEditor → GenerateVideo → downstream node (e.g. Result Viewer); cascade run; downstream must fire only after video completes.
